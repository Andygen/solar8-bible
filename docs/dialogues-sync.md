# Реплики Bible ↔ игра

Общий формат: `assets/dialogues.json` на сайте и
`assets/localization/dialogues.json` в игре. Начальная передача содержит реплики
реализованных миссий и ангара, а не все будущие главы Bible.

## Первое подключение сайта

Скопировать содержимое пакета `exports/bible-dialogues/` в репозиторий Bible.
Опубликовать `assets/dialogues.json` и `dialogues.html` через обычный процесс сайта.
`dialogues.html` показывает оба языка из JSON, без второй копии текста в HTML.
Добавить ссылку на эту страницу в навигацию Bible.
До публикации файла команда `--pull` завершится ошибкой без изменения игры.
Сам игровой репозиторий не публикует сайт.

Существующие сценарные HTML-страницы не обновляются от одного размещения JSON.
Чтобы сделать их представлением этого же источника, связать элементы реплик с
ID из JSON и заполнять их `textContent`. Нельзя параллельно редактировать старую
HTML-копию реплики и JSON. На время переноса редактировать реализованные игровые
реплики только в общем JSON; литературный сценарий и будущие главы хранить отдельно.

## Редактирование и синхронизация

После начальной публикации мастер — JSON в репозитории Bible. Редактор меняет
`en`, `ru`, при необходимости ссылку `bible` и `relationship`, затем `revision`.
Оба языка обязательны. Постоянные `id` нельзя пересоздавать из английского текста.
`speaker`, `mission`, `context`, `trigger`, `order` и `legacy_text` — связи с игрой;
их изменение требует отдельной миграции игровых данных. Порядок внутри одного
события задан кодом; `order` — индекс исходной записи, не время запуска реплики.
Пороги здоровья, таймеры и условия диалогов остаются в игровых сценариях.

Из корня игрового проекта:

```sh
node tools/sync_dialogues.cjs --pull
node tools/sync_dialogues.cjs --check
node tools/localization_catalog.cjs --check
node tools/dialogue_sync_test.cjs
```

Для передачи без сети: `node tools/sync_dialogues.cjs --import путь/dialogues.json`.
Проверка проходит до записи; удалённые используемые ID, неизвестные персонажи,
пустой перевод и несовместимые параметры `%s`/`%d` блокируют импорт.
`build/dialogue-sync/previous.json` хранит предыдущую копию,
`last-changes.json` — список изменившихся ID. Посмотреть diff и прогнать
`tools/localization_smoke.gd`, особенно после удлинения фраз.
В APK включается локальный JSON; сеть при игре не используется.

## Новые диалоги

Добавить уникальный `dlg.*` ID и оба языка в мастер JSON. Для новой игровой сцены
добавить ссылку на ID и запись в `assets/localization/dialogue-bindings.json`.
Новая запись сама по себе не запускает диалог. Персонажи проверяются по известному
списку; нового персонажа сначала согласовать и добавить в игру/валидатор.
Форматируемые строки использовать как `tr("dlg.example.rook.001") % argument`.
Меню и технический UI остаются в `messages.json`.

## Сверка со сценарием

`verbatim_en` означает найденное точное английское совпадение в текущих сценарных
страницах Bible. Это не подтверждение редакторской приёмки русского перевода.
`gameplay_adaptation` сохраняет текущий игровой текст, который отличается от
литературной версии или объясняет механику. Не выдавать адаптацию за дословный канон.
`legacy_text` — неизменяемый технический псевдоним для старых составных подписей;
не редактировать как дополнительный перевод. Новые сцены используют только ID.

Экспорт первоначального пакета: `node tools/sync_dialogues.cjs --export`.
После подключения сайта не перезаписывать его мастер устаревшей игровой копией.
