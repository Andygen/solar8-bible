# Как дописывать реплики: аудит сайта 27.09.2026

## Проверенное состояние

Опубликованный `assets/dialogues.json` содержит 282 записи, совпадает с игровым
каталогом и проходит игровой валидатор. `dialogues.html` читает этот JSON.
Сценарные страницы подставляют RU/EN через `assets/dialogue-bindings.js` по
`data-dialogue-id`; английский HTML остаётся запасным текстом на случай ошибки сети.
Веб-интерфейс сейчас служит просмотром и поиском, не редактором с сохранением.

Отчёт сайта: `https://andygen.github.io/solar8-bible/docs/dialogue-integration-report.md`.
На двух проверенных страницах Mercury/Venus и Earth/Mars — 272 блока `.text`,
152 связаны с ID, 120 не связаны. У 10 несвязанных блоков найдено точное совпадение
EN в каталоге; это кандидаты на привязку, не разрешение автоматически связывать
одинаковые фразы разных персонажей, миссий или веток. Остальные 110 включают
варианты литературного текста и будущие сцены; это не 110 обязательных новых
реплик для уже готовой игры. `unbound-lines.json` в пакете содержит результаты.

## Где писать

1. Черновик сцены и условия её появления обсуждать в сценарии соответствующей
   миссии. Готовый текст переносить в `assets/dialogues.json` в репозитории Bible,
   сразу с EN/RU. Отдельная игра не должна становиться вторым редактором текста.
2. Для правки уже существующей реплики изменять EN/RU по её прежнему ID. Для
   самостоятельной новой реплики создавать новый ID, например
   `dlg.mars_4_2.briefing.max.001`. Не копировать другую строку с тем же ID.
3. Заполнять `speaker`, `mission`, `context`, `trigger`, `order`, ссылку `bible` и
   корректный `relationship`. У существующих записей эти игровые связи защищены
   контрактом. `legacy_text` новым строкам не нужен.
4. Добавить `data-dialogue-id` к соответствующей реплике сценарной страницы и
   обновить её генерируемый английский запасной текст принятым на сайте способом.
   Если подходящий ID уже существует, не создавать дубль.
5. Проверить каталог и контракт сайта, обновить `revision`, опубликовать.
   Новые ID добавлять в контракт явно после проверки; не пересоздавать весь
   контракт из произвольного JSON, иначе защита существующих связей теряет смысл.
6. В игре выполнить `node tools/sync_dialogues.cjs --pull`. Исправления текста
   существующих ID сразу доступны в локальном запуске. Новые реплики впервые
   подключаются к брифингу, событию, радиопередаче или завершению миссии в коде,
   с добавлением `dialogue-bindings.json`. Затем проверяются локализация и сцена.
   Уже установленный APK меняется только после новой сборки и установки.

## Как показывать готовность

Нужно различать «есть EN/RU в каталоге», «есть на странице» и «используется игрой».
Это независимые признаки. `relationship` описывает связь с литературным текстом,
а не готовность к игре. В пакете есть снимок `game-dialogue-usage.json` с реально
подключёнными ID; его можно использовать на сайте для отметок. После разработки
новых миссий снимок нужно обновлять из игрового репозитория.

Сначала привязать 10 найденных кандидатов после проверки говорящего и ситуации.
Затем сверить несвязанные реплики реализованных миссий 1-1…4-1 с текущими игровыми
адаптациями. Будущие главы дописывать целыми сценами: брифинг → события → исходы.
Не включать все литературные реплики в радиообмен автоматически: это меняет
темп, условия и приоритеты. Сам JSON не запускает событие в игре.

## Две исправляемые записи из отчёта сайта

- `dlg.chapter_transmission.rook.001` — ошибочный результат первоначального
  переноса служебного имени ANDYGEN. В игре восстановлена проверка имени, эта
  запись удалена из игровых привязок. Удалить её из мастер-JSON и контракта сайта
  согласованной миграцией. Игра теперь примет такой импорт. До обновления сайта
  локальный каталог сохраняет эту неиспользуемую запись, чтобы не править мастер
  в двух местах.
- `dlg.game.rook.007` — рабочая игровая реплика про питание Warden от коллекторов.
  По отчёту сайта точной пары в сценарии нет. Сохранить ID и игровой текст,
  сменить `relationship` на `gameplay_adaptation`; не привязывать насильно к
  похожей литературной фразе.

Пакет является результатом аудита, не заменой опубликованного каталога или сайта.
