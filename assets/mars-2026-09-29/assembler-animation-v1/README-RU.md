# Assembler Prime — подвижная 2D-сборка v1

Дата: 26.09.2026. Дополнение к `solar8-assets-handoff-2026-09-26`, отдельная версия для анимации. Старые цельные фазы и перспективные концепты не заменять автоматически.

## Готово в этом комплекте

10 прозрачных PNG: корпус, основание шарнира, плечо, предплечье, один палец клешни, бур, диск пилы, створка отсека, каретка пресса и чужой модуль. Семь ресурсов новые; три звена/основание повторно использованы из проверенного захвата.

На этих деталях собраны четыре руки: два открывающихся захвата, бур и вращающаяся дисковая пила. Плечи и локти двигаются вокруг совпадающих осей. Одна деталь пальца используется зеркально для правой стороны; один PNG створки — для двух половин люка. Все движения выполняются в плоскости экрана.

Открой `demo.html` в браузере. Встроенные изображения позволяют смотреть демонстрацию без установки пакетов. Выбери состояние, нажми «Показать движение» или перемещай ползунок.

## Состояния демонстрации

1. Производство: отсек закрыт, каретка совершает небольшой ход, руки работают.
2. Охлаждение: створки расходятся на 35 условных пикселей каждая, видны внутренние охлаждающие поверхности.
3. Чужой модуль: створки расходятся на 98 пикселей, каретка плавно отводится вверх, открывается гладкий чёрный блок.

Это визуальные состояния для разработки. Порог здоровья, спавн дронов, ремонт брони, сканирование Максом и прочие сценарные события должны управляться игровым кодом. Движение бура показано как движение руки целиком: вращение винтового сверла вокруг его продольной 3D-оси не имитируется вращением всего PNG.

## Для Bible

Добавить подраздел к Assembler Prime: «Подвижная 2D-сборка v1». Показывать вместе с исходными фазами, а не молча подменять их. Подпись: «Четыре манипулятора, раскрытие захватов и центрального отсека; проверено в демонстрации Canvas. Игровая логика и приёмка в движке отдельно».

Скопировать `assets/` в отдельную папку сайта, например `assets/rig/assembler-v1/`. Имена из manifest стабильны. Для просмотра дать ссылку на `demo.html`; исходные PNG доступны отдельно. Дату/название миссии и описание поведения брать из текущего сценария.

## Для игры

`assembler-rig.js` содержит функцию `makeAssemblerRig(images)`, которая принимает словарь загруженных изображений по `id` из `manifest.json`. Подключается обычным script до использования функции. Отдельные библиотеки не нужны.

```js
const rig = makeAssemblerRig(images);
ctx.save();
// Размеры самой сборки заданы в условных пикселях; масштабировать общий контейнер.
ctx.translate(screenOffsetX, screenOffsetY);
ctx.scale(bossScale, bossScale);
rig.draw(ctx, { phase: 3, t: cycleProgress, opening: 98 });
ctx.restore();
```

`t` от 0 до 1 — один цикл движения. `opening` задаёт смещение каждой створки. Для смены состояния интерполировать его, например smoothstep за 650 мс; каретка и видимость ядра привязаны к этому параметру. `phase` — тег состояния для внешней логики; поза отсека определяется `opening`. Игровой цикл самостоятельно очищает canvas. `joints: true` включает диагностические оси; передай конкретный CSS-цвет в `jointColor`.

Начало корпуса в эталоне `(550,535)`, его pivot `(627,627)`, scale `0.5`. Demo использует canvas 1100×850 и дополнительное смещение `(0,-150)` для компактного кадра. Не применяй это смещение к каждому звену отдельно.

Координаты — X вправо, Y вниз. Углы внутри JS в радианах, положительное вращение по часовой стрелке. Пивоты в полных исходных PNG до обрезки прозрачных полей. Полные значения приведены в `rig-data.json`; порядок наложения и формулы — в `assembler-rig.js`.

Не обрезай текстуры без пересчёта pivot. Не заменяй чёрный цвет прозрачностью. Размеры исходников различаются: створка 887×1774, остальные 1254×1254. Встроенная demo использует уменьшенные копии для просмотра; игровые PNG сохранены в исходном разрешении.

Отверстия звеньев закрыты маленькими копиями основания; эти крышки — обязательная часть сборки. Две клешни используют четыре экземпляра пальца, два зеркально. Не зеркалить всю готовую руку вместо иерархии: это изменит ориентацию суставов.

## Проверка и границы

Загружены все 10 PNG; проверены 101 положение общей траектории и непрозрачность 12 осей рук. Просмотрены крайние положения и три состояния; проверены ползунок, запуск/окончание цикла и смена состояния в среде Canvas. Это не полноценный тест браузерной вёрстки или мобильного игрового движка.

Корпус и инструменты собраны в общую проекцию для 2D. В растровых материалах остаются нарисованные фаски и свет: настоящего 3D-поворота, обратных сторон и динамического освещения нет. Запечённые блики пилы вращаются вместе с текстурой. Дым, искры, взрывы, hitbox и баланс не входят в комплект.

Руки, пальцы, пила, бур, створки, пресс и модуль теперь отдельные узлы, поэтому их можно скрывать или отделять при разрушении. Трещины, обломки и разрушаемые секции самого корпуса отдельно ещё не нарисованы. Сервисные панели и ячейки корпуса остаются внутри одного PNG; анимация регенерации брони требует игровых эффектов.

## Источник и происхождение

Сценарный визуальный ориентир: https://andygen.github.io/solar8-bible/art-briefs-earth-mars.html (проверен 26.09.2026). Прозрачные детали созданы встроенной генерацией изображений; `prompts.json` сохраняет запросы этого прохода. Первый неудачный вариант пальца с лишними звеньями исключён из комплекта.

Это завершённая демонстрационная сборка механизма, а не заявление о полной готовности боя с боссом. Перед подключением в игру проверить нужные траектории, столкновения и ограничения именно в её масштабе и камере.
